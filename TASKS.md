# TASKS.md: SADA (Semantic Attribute-Driven Anchoring) Implementation Plan

## Project Overview
This project extends the "VtT" model, a fine-tuning method for CLIP in Source-Free Cross-Domain Few-Shot Learning (SF-CDFSL), to implement "SADA (LLM-driven Semantic Attribute Anchoring & Orthogonal Decomposition)".
The goal is to use multiple semantic attributes generated by a local LLM to separate domain noise from the visual encoder and align pure semantic information with the text space.

## Directory Structure (Actual Codebase)

## Phase 3: Implementation of Orthogonal Feature Decomposition
Add a module to `VtT.py` that separates domain noise and semantic information from the visual features.

- [ ] Add a new `OrthogonalDecomposition` class (`nn.Module`) in `VtT.py`.
  - [ ] Define a single linear projection `proj_semantic: nn.Linear(dim, dim, bias=False)` that acts as the learnable projection matrix $P$.
  - [ ] Compute `V_semantic = proj_semantic(V)`.
  - [ ] Compute `V_domain = V - V_semantic` (guaranteed orthogonal by construction, no additional constraint needed).
  - [ ] **Do not** use two independent projections — that does not enforce $V = V_{semantic} + V_{domain}$ without explicit loss terms.

## Phase 4: Modification of CLIP Text Encoder for Multi-Token Injection
Extend `clip/model.py:encode_text()` to accept K absorber tokens and inject them at K consecutive positions.

- [ ] Modify `clip/model.py:encode_text()`.
  - [ ] Change the `inject` parameter to accept a tensor of shape `(batch, K, dim)` in addition to the current `(batch, dim)` form.
  - [ ] When `inject` has shape `(batch, K, dim)`, inject tokens at positions `5` through `5+K-1`:
    ```python
    x[:, 5:5+K] = inject  # inject K absorber tokens
    ```
  - [ ] Verify that the CLIP context length (77) is not exceeded: `5 + K + len(template_tokens) <= 77`. For K=5 this is safe with the `'a photo of a x.'` template (≈9 tokens).
  - [ ] Keep the existing single-token path (`inject` shape `(batch, dim)`) working for backward compatibility.

## Phase 5: Implementation of the Multi-Head TIA Module
Expand the original Text Encoder Information Absorption (TIA) module in `VtT.py` to produce K absorber tokens.

- [ ] Modify or extend `Mamba_Net` in `VtT.py`.
  - [ ] Add a `MultiHeadTIA` projection head: `nn.Linear(dim, K * dim, bias=False)`.
  - [ ] Accept `V_semantic` (output of `OrthogonalDecomposition`) as input.
  - [ ] Output K absorber tokens `A' ∈ R^(batch, K, dim)` reshaped from the linear projection.
  - [ ] Pass `A'` to the modified `clip_model.encode_text(..., inject=A')` to produce `mae_image_embeddings`.

## Phase 6: Updating Loss Functions
Update the loss computation in `VtT.py:run_lora()` with multi-head $L_{VtT}$ and orthogonal loss.

- [ ] Modify the loss section in `VtT.py:run_lora()`.
  - [ ] **Multi-Head $L_{VtT}$:**
    - Compute cosine similarity between each absorber token $A'^{(i)}_k$ and the corresponding pre-extracted text attribute feature $t_{y_i, k}$ from `text_attr_features`.
    - Formula: $L_{VtT} = -\frac{1}{N}\sum_{i=1}^N \frac{1}{K}\sum_{k=1}^K \cos(A'^{(i)}_k,\ t_{y_i,k})$
    - **Note:** Do NOT use $\cos(V_{semantic}, A'_k)$ — that is self-referential since $A'_k$ is derived from $V_{semantic}$.
  - [ ] **Orthogonal Loss ($L_{ortho}$):**
    - Formula: $L_{ortho} = \frac{1}{N}\sum_{i=1}^N |\cos(V_{semantic}^{(i)},\ V_{domain}^{(i)})|$
    - This serves as a soft regularizer; the architecture already enforces exact orthogonality by construction (Phase 3).
  - [ ] **Combined Loss:**
    - $L_{comb} = L_{ce} + \beta L_{VtT} + \gamma L_{ortho}$
    - Initial value: $\gamma = 0.1$.

## Phase 9: mae_loss_img の InfoNCE 化（案A）

### 目的
fine_acc をさらに向上させる。
現状の `-diag(image_features @ mae_text_features.T).mean()` は正例を引き寄せるだけで
負例を考慮しない。InfoNCE（cross-entropy）化により、クラス間識別シグナルを強化し
LoRA への学習勾配をより鮮明にする。

### 現状と期待値
| 指標       | 元論文  | 79340 (現状) | 期待値  |
|------------|---------|--------------|---------|
| fine_acc ★ | 85.14%  | 85.54%       | >85.5%  |

### 変更箇所
`VtT.py` — `mae_loss_img` の計算式のみ変更（2行）

### 変更内容

**変更前:**
```python
mae_cosine = image_features @ mae_text_features.t()
mae_loss_img = -torch.diag(mae_cosine).mean()
```

**変更後:**
```python
mae_cosine = image_features @ mae_text_features.t()  # (batch, batch)
targets = torch.arange(len(image_features), device=image_features.device)
mae_loss_img = F.cross_entropy(mae_cosine, targets)
```

### 根拠
- `cross_entropy(logits, arange)` は InfoNCE と等価
- 各行 i について「列 i のスコアが最大になれ」を要求
  → 正例を引き寄せ、かつバッチ内の他サンプルを負例として押しのける
- 元の `-diag(...).mean()` は正例引き寄せのみ（負例への勾配ゼロ）
- `mae_text_features[i]` は画像 i の absorber token から生成されるため
  バッチ内で同クラスが複数あっても各特徴は画像固有 → `arange` ラベルで正しい

- [x] 計画記述
- [x] 実装（`VtT.py:411-414`）
- [x] 実験実行（VtT.79382）
- [x] 結果確認 → **失敗（fine_acc 85.54% → 80.90%, −4.64pt）**

### 失敗原因
バッチ内に同クラスの画像が複数存在する（batch_size=25, 5-way → 各クラス約5枚）ため、
InfoNCE化により同クラス同士を負例として押しのけてしまい、LoRA に有害な勾配が流れた。
combine_acc は 36.55% → 78.30% と劇的改善したが、fine_acc が犠牲になった。

### 対応
- [ ] `mae_loss_img` を元の `-diag(...).mean()` に戻す（次タスク）

## Phase 11: Supervised Contrastive Loss（案A'）

### 目的
案A（InfoNCE）の失敗から、「同クラス同士を押しのけない」損失設計が必要と判明。
Supervised Contrastive Loss を導入することで、同クラスは正例として扱い、
他クラスのみ負例として押しのける。InfoNCE の識別力を保ちつつ、
fine_acc を悪化させた同クラス押しのけ問題を回避する。

### 現状（K=5維持）と期待値
| 指標       | 元論文 | 79340 (-diag) | 79382 (InfoNCE) | 期待値 |
|------------|--------|---------------|-----------------|--------|
| fine_acc ★ | 85.14% | 85.54%        | 80.90%          | >85.5% |
| combine_acc| 80.99% | 36.55%        | 78.30%          | >50%   |

### 変更箇所
`VtT.py:411-417` — `mae_loss_img` の計算式

### 変更内容
```python
# Supervised Contrastive: same-class pairs are positives
sc_logits = logit_scale * image_features @ mae_text_features.t()  # (B, B)
labels_eq = (y_batch.unsqueeze(0) == y_batch.unsqueeze(1)).float()  # (B, B)
log_prob = F.log_softmax(sc_logits, dim=1)
mean_log_prob_pos = (labels_eq * log_prob).sum(dim=1) / labels_eq.sum(dim=1).clamp(min=1.0)
mae_loss_img = -mean_log_prob_pos.mean()
```

### 設計判断
- **`logit_scale` を乗算**: 生 cosine（[-1,1]）だと softmax が平坦化して勾配が弱い。
  CE loss と同じスケール（`cosine_similarity = logit_scale * ...` 行と一致）に揃える。
- **自己ペアも正例に含める**: `y_i == y_i` は常に True なので `labels_eq` の対角は1。
  これにより最低でも instance-level alignment は保たれる。
- **正例で平均**: `labels_eq.sum(dim=1)` で割ることで、クラス頻度が偏っても安定。

### 根拠
- batch_size=25, 5-way → 各クラス約5枚。InfoNCE では同クラス4枚を負例にしてしまう。
- Supervised Contrastive はこの 4枚を正例として扱う → 同クラス凝集 + 他クラス分離
